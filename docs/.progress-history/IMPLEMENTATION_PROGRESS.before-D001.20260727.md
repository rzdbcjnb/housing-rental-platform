## 当前阶段：阶段 0 - 固定基线和修复当前检索红线

当前状态：`BLOCKED - 等待用户确认实施选项`

### 0.1 最小人工检索评测集

- [ ] 确定评测集规模、数据来源和文件格式。
- [ ] 建立版本化查询样本与相关房源标注。
- [ ] 覆盖纯结构化、纯语义、混合条件、零命中、冲突条件和向量库不可用场景。
- [ ] 实现可重复执行的离线评测程序。
- [ ] 输出 Recall@K、Precision@K、MRR/nDCG、硬条件违反率、零命中正确率和延迟。

注意事项：

- 评测集必须基于一份固定的房源数据快照，否则不同日期的指标不可比较。
- “相关房源”需要人工标注；不能用当前检索结果反向生成标准答案。
- 首批数据字段较少，通勤、家电等尚未建模的查询只能标记为当前阶段不支持，不能把它们计为模型召回失败。
- 评测数据不得包含身份证、产权证明、精确门牌等敏感信息。

### 0.2 修复纯语义零召回假命中

- [ ] 为向量检索结果定义可区分的状态，而不是只返回 `active` 布尔值。
- [ ] 修复“向量检索成功但 ID 为空时查询任意公开房源”的行为。
- [ ] 增加单元测试和接口级回归测试。

注意事项：

- 必须区分“检索成功但无结果”和“向量库不可用”，两者不能采用同一降级语义。
- 零命中是否返回空列表、仅结构化热门结果或提示用户放宽条件，需要用户确认。
- 修改返回模型时需检查所有调用方，避免前端把基础设施故障展示成正常零结果。

### 0.3 修复结构化条件下的无序候选截断

- [ ] 确定结构化条件查询的候选生成与排序策略。
- [ ] 移除无解释的 `LIMIT 50`，或替换为稳定且可解释的候选策略。
- [ ] 保证硬条件在截断前完整执行。
- [ ] 增加超过 50 条候选时的回归测试。

注意事项：

- 当前房源字段和索引有限，直接取消上限可能产生性能问题。
- 若采用分页或扩大候选池，必须有稳定 `ORDER BY`，否则结果会随执行计划变化。
- 排序权重必须通过评测校准，不能在没有数据时宣称最优。

### 0.4 向量 Collection 健康检查

- [ ] 确定健康检查暴露级别和失败语义。
- [ ] 检查 VectorStore Bean、Collection 可访问性、文档数量和最近同步状态。
- [ ] 增加健康状态测试与运维说明。

注意事项：

- 不能仅以 HTTP 可连接作为健康；空 Collection、索引陈旧同样会导致业务不可用。
- 健康接口不得泄露连接凭据、内部地址或房源敏感元数据。
- 启动阶段强制失败还是运行时降级，需要用户确认。
