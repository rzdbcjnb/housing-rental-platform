# 阶段 1 数据库设计决策

> 开始日期：2026-07-27  
> 当前状态：逐表商定中  
> 实施边界：本文只记录已确认设计；在全部相关表和迁移方案确认前，不执行生产 DDL

## 1. 已确认：`house` 主表

### 1.1 表职责

`house` 是房源聚合根，只保存房源身份、生命周期以及高频筛选、排序所需的稳定单值事实。费用、精确位置扩展、房间、家电、设施、媒体、字段来源和审核历史由后续表承载。

### 1.2 保留字段

| 字段 | 处理与语义 |
| --- | --- |
| `id` | 保留主键，所有现有业务外键保持稳定 |
| `title`、`description` | 保留展示字段；描述不作为结构化事实来源 |
| `price` | 保留字段名，明确表示月租金额 |
| `area` | 保留字段名，明确表示建筑面积 |
| `rooms` | 保留兼容，由户型数量派生，不允许独立修改 |
| `bedroom_count`、`living_room_count`、`bathroom_count`、`kitchen_count` | 保留结构化户型数量 |
| `house_type` | 保留字段名，表示整租或合租 |
| `region_id` | 保留行政区域关联 |
| `address_detail` | 过渡期保留，后续由 `house_location` 提供规范位置数据并兼容映射 |
| `image` | 过渡期保留，后续镜像 `house_media` 封面 |
| `landlord_id` | 保留房东资料关联 |
| `status`、`is_active` | 过渡期保留，明确生命周期状态与运行启用状态 |
| `click_count` | 保留点击统计 |
| `create_time`、`update_time` | 保留创建和更新时间 |

### 1.3 新增字段

| 字段 | 类型建议 | 新版发布规则 | 说明 |
| --- | --- | --- | --- |
| `usable_area_sqm` | `DECIMAL(8,2) NULL` | 可选 | 套内或实际使用面积 |
| `floor_number` | `SMALLINT NULL` | 必填 | 所在楼层；数据库允许历史未知和地下层负数 |
| `total_floors` | `SMALLINT NULL` | 必填 | 建筑总楼层 |
| `has_elevator` | `BOOLEAN NULL` | 必填 | `NULL` 为未知，不等同于没有电梯 |
| `has_balcony` | `BOOLEAN NULL` | 必填 | `true/false` 必须由房东明确，`NULL` 只允许历史或未完成草稿 |
| `orientation` | `VARCHAR(30) NULL` | 必填 | 使用标准枚举，不保存任意同义文本 |
| `decoration_level` | `VARCHAR(30) NULL` | 必填 | 毛坯、简装、精装等标准代码 |
| `heating_type` | `VARCHAR(30) NULL` | 必填 | 无供暖也使用明确代码，避免与未知混淆 |
| `data_schema_version` | `SMALLINT NOT NULL` | 系统写入 | 区分历史房源和新版完整房源 |
| `completeness_score` | `DECIMAL(5,2) NOT NULL` | 系统计算 | 不接受客户端或模型直接提交 |
| `verification_level` | `VARCHAR(20) NOT NULL` | 系统计算 | 声明、部分核验、已核验等等级 |
| `version` | `BIGINT NOT NULL` | 系统维护 | 乐观锁与用户确认版本绑定 |
| `published_at` | `DATETIME NULL` | 审核通过写入 | 首次公开时间 |
| `last_verified_at` | `DATETIME NULL` | 核验后写入 | 最近核验时间 |
| `deleted_at` | `DATETIME NULL` | 删除时写入 | 采用软删除，保留历史业务引用 |

### 1.4 明确排除

- 不保存阳台数量，只保存是否有阳台。
- 不保存建筑年份。
- 押金、付款周期、起租日期、宠物等租赁条件不放主表。
- 物业、水电、供暖等费用不放主表。
- 小区、精确门牌、坐标和地图 POI 不作为主表新增字段。
- 房间、家电、设施和媒体不压缩为主表 JSON。

### 1.5 校验和兼容规则

1. 历史房源允许新增业务字段为 `NULL`，显示“信息待补充”，不得伪造默认值。
2. `data_schema_version >= 2` 的房源在提交审核前必须补齐新版核心字段。
3. `has_balcony` 是发布 Agent 和传统表单的必填字段；模型不得根据图片或描述自行确认。
4. 新版房源 `has_balcony IS NULL` 时管理员不得审核通过。
5. 删除接口改为软删除：写入 `deleted_at`，并设置 `status=offline`、`is_active=false`。
6. 旧接口响应继续包含 `price`、`area`、`rooms`、`house_type`、`image` 和 `address_detail`。

## 2. 已确认：`house_location` 位置表

### 2.1 表职责

`house_location` 与 `house` 一对一，保存小区、楼栋、可选精确门牌和地图定位结果。精确地址与坐标属于受保护数据，不能因为同表存储而直接进入公开接口。

### 2.2 字段

| 字段 | 类型建议 | 新版发布规则 | 说明 |
| --- | --- | --- | --- |
| `house_id` | `BIGINT` | 系统写入 | 主键兼外键，保证一套房源只有一条位置记录 |
| `community_name` | `VARCHAR(100)` | 必填 | 小区或公寓名称 |
| `building_no` | `VARCHAR(30) NULL` | 条件必填 | 存在楼栋编号时必须填写 |
| `unit_no` | `VARCHAR(30) NULL` | 可选 | 保存单元号；没有单元划分时为空 |
| `room_no` | `VARCHAR(30) NULL` | 可选 | 保存房间号但不作为发布必填项 |
| `address_detail` | `VARCHAR(300)` | 必填 | 完整规范地址，属于私密字段 |
| `map_provider` | `VARCHAR(20) NULL` | 地图阶段写入 | 例如 `amap` |
| `map_poi_id` | `VARCHAR(100) NULL` | 地图阶段写入 | 地图服务标准 POI 标识 |
| `longitude` | `DECIMAL(10,7) NULL` | 分阶段必填 | 经度 |
| `latitude` | `DECIMAL(10,7) NULL` | 分阶段必填 | 纬度 |
| `coordinate_system` | `VARCHAR(20) NULL` | 有坐标时必填 | `GCJ02`、`WGS84` 等，防止坐标系混用 |
| `location_precision` | `VARCHAR(20)` | 系统写入 | `community/building/exact` 等标准代码 |
| `location_status` | `VARCHAR(20)` | 系统写入 | `pending/success/ambiguous/failed` |
| `geocoded_at` | `DATETIME NULL` | 系统写入 | 最近一次成功或有效定位时间 |
| `geocode_metadata` | `JSON NULL` | 系统写入 | 地图服务非核心白名单扩展信息 |
| `create_time` | `DATETIME` | 系统写入 | 创建时间 |
| `update_time` | `DATETIME` | 系统写入 | 更新时间 |

### 2.3 字段归属

- `building_no` 保存于 `house_location`。
- `floor_number` 与 `total_floors` 已保存于 `house`，位置表不重复。
- 附近地铁站、公交站和通勤路线不放本表，由地图与通勤阶段的计算结果表承载。
- 过渡期继续维护 `house.address_detail`，用于兼容旧接口；规范来源逐步切换到本表。

### 2.4 隐私与发布规则

1. 普通租客只看到行政区、街道和小区名称。
2. 楼栋、单元、房间号、完整地址和精确坐标只对房东、管理员及受控内部服务开放。
3. 阶段 1 要求完整文本地址，但经纬度允许为空，`location_status=pending`。
4. 地图服务完成后，新版房源审核通过前必须达到 `location_status=success`。
5. 发布 Agent 不得生成坐标，只能展示地图 POI 候选并让用户确认。
6. `unit_no` 与 `room_no` 均可选；未填写不降低到“发布不完整”。

- 尚未编写或执行 DDL。
- 尚未修改 Java、测试 schema、前端或真实数据。
