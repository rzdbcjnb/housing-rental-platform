## 截断验证

- 95 条结构化降级查询继续先在 MySQL 执行完整硬条件过滤。
- 14 条查询返回超过 20 套房源，其中 2 条达到内部上限 50 套。
- 真实数据库中出现 56 条和 62 条硬筛候选，证明 Mapper 不再在 50 条处提前截断；服务层在全局排序后才截取前 50 条。
- Agent 工具层的 `MAX_SEARCH_LIMIT=20` 未修改，因此对外一次最多 20 套的交互边界保持不变。

## 指标解释

Recall@50 已具备独立区分力，并较 0.2 明显提升。Recall@20 和 nDCG@20 的轻微变化来自候选生成语义发生改变：0.2 在数据库返回的任意 50 条子集内排序，0.3 在全部硬筛候选中排序，并以房源 ID 作为同分稳定次序。在向量被强制关闭的本检查点中，大量候选同分，因此该变化不代表向量相关性变差。

本报告仍只验证 MySQL 降级路径，因此不能用其中的 Recall 评价向量语义质量。后续已确认 Spring AI 实际使用 `SpringAiTenant/SpringAiDatabase/housing-rag`，并通过独立的真实 BGE + Chroma 冒烟测试完成链路验收；结果见同目录 `chroma-smoke/`。
