## 状态分布

- `DEGRADED_STRUCTURED`：95 条。向量库不可用，但存在硬条件，因此只执行 MySQL 结构化筛选。
- `RETRIEVAL_UNAVAILABLE`：50 条。向量库不可用且没有硬条件，因此不返回任意公开房源。
- `MATCHED`：0 条。该检查点强制关闭向量检索，不能产生正常语义命中。
- `NO_MATCH`：0 条。该状态需要向量检索成功且确实零命中，本检查点不覆盖该运行环境，已由服务层测试覆盖。

## 结论

0.2 的目标是消除假命中，而不是在向量库故障时维持表面召回率。Recall 和 nDCG 的下降来自 50 条无硬条件查询不再返回任意房源；这是真实暴露基础设施不可用后的预期结果，不能通过恢复旧兜底提高指标。

Chroma 恢复后仍需使用同一数据集补跑向量正常检查点，验证 `MATCHED` 和 `NO_MATCH` 的真实分布及语义召回质量。
